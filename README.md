# 掌勺 · 烹饪陪伴助手

当前版本聚焦「选菜谱 → 备菜建议 → 结合实际步骤答疑并做完一餐」。内置 34 道菜、41 份可溯源做法；本地未收录时默认联网检索 HowToCook 固定版本的公开索引并读取完整正文。无需模型 API，问答在浏览器本机按明确的规则处理。

## 已实现

- 菜名 `Dish` 与具体做法 `Recipe` 分开；一个菜名可关联多份独立配方，各有稳定 ID、做法名称、配方修订号和来源。
- 首页、菜谱详情和菜谱库支持“换一种做法”，展示食材差异、锅具、参考时间及各自来源；确认后原子更新清单、预算和步骤，其他菜的配方保留。
- 开始烹饪后锁定当前做法；改灶台、已有食材和刷新恢复均使用本餐保存的配方、步骤与来源，不重新读取最新版覆盖。
- 本机保存格式 v3 包含所选做法快照；旧 v1/v2 菜单与有效进度迁移到默认做法，异常 v3 数据明确提示重新核对。

- 34 道家常菜，支持菜名、常用别名与食材搜索，以及荤菜、水产、蔬菜、蛋豆、汤羹、主食、凉菜分类。
- 本轮新增 24 道来自 HowToCook 参考资料的整理版；链接固定到 `308cc8b7dab1da84b20e7fafdf836a715437f582` 快照，记录核对日期、改编说明。
- 蒸锅作为独立资源，泡发、腌制不占灶台；等待阶段按类型显示，冷藏泡发不可用延时按钮任意追加。

- 按菜名、人数、预算、一口或两口灶及可用时间建立整餐计划。
- 缩放食材用量、合并共用食材、扣除已备足量食材，提供参考包装与可复制、下载的备菜建议。
- 费用以区间展示，标明为内部参考值，未含配送、包装；没有商家商品、库存、订单或支付能力。
- 菜谱详情显示整理日期、原创或参考来源，以及与参考做法的差异；参考链接可直接打开。
- 烹饪按步骤依赖推进，一个人操作，遵守当前灶台数量及锅具占用；快手热菜接近长炖菜完成时再推荐。
- 内置答疑读取当前菜单、人数、步骤、计时、已有食材及选择的菜品范围。
- 支持份量、火候、加水、缺料、口味、步骤顺序、剩余时间及单灶重排等常见问题。
- 多道菜可能对应问题时先澄清；未收录的菜或问题明确告知范围；不判断食物实际熟度。
- 接近炖煮参考结束时，仍硬的红烧肉或排骨可由用户确认延长 10 分钟；尚早时先提示按原计时观察。已经逾时的提醒从确认时重新计足追加时长，保留实际开始时间。
- 单灶调整保留已完成步骤和计时；两锅已同时加热时，拒绝直接切换为单灶，提示先处理现场。
- 缺料建议可纠正「家里已备」假设；动作按钮过期后不能继续修改旧计划。
- 进度、单灶设置、延长时间与最近 20 条问答保存在本机，刷新后恢复。
- 旧版 v1 菜单、有效步骤进度迁移到 v2；旧模拟订单不进入当前流程。

## 运行与验证

需要 Node.js 22.13+。原生 TypeScript 测试使用 Node.js 24。

```sh
npm run install:ci
npm run dev -- --host 127.0.0.1
npm test
npm run typecheck
npm run build
```

开发地址默认 `http://127.0.0.1:5173/`，以启动输出为准。

## 主要结构

- `app/page.tsx`：选菜、备菜、烹饪三个界面与本机进度保存。
- `components/kitchen/cooking-help.tsx`：本餐问答、澄清选择、回答依据及确认操作。
- `lib/kitchen/web-recipes.ts`：下厨房公开参考的独立配方与原作者、原页链接。
- `lib/kitchen/library.ts`：新增 24 道 2 人基准配方、原始路径、固定快照和逐菜改编说明。
- `lib/kitchen/variants.ts`：7 份额外做法及逐份来源；来源事实核对后独立整理，文字和图片不复制。
- `lib/kitchen/snapshots.ts`：本餐做法与来源快照、本机恢复数据校验。
- `lib/kitchen/catalog.ts`：2 人基准整理配方、规范食材与内部包装参考。
- `lib/kitchen/sources.ts`：每道菜的来源、参考链接、改编说明、版本和答疑依据。
- `lib/kitchen/engine.ts`：需求合并、购买建议、预算区间、灶台调度和计时更新。
- `lib/kitchen/advisor.ts`：有限规则答疑，输出正文、澄清选项、依据和可选的结构化动作。
- `scripts/generate-dish-art.mjs`：为 34 道内置菜各生成一张原创俯视插画，输出到 `public/food/dish/<dishId>.svg`；改图后运行 `node scripts/generate-dish-art.mjs` 重新生成。联网导入的菜仍使用 `public/food/` 下的通用插画。
- `tests/`：份量、计划资源、完整单/双灶流程、问答范围、计时与动作校验。

## 例子

「红烧肉、番茄炒蛋、山药排骨汤，2 人」默认双灶参考约 93 分钟，单灶参考约 146 分钟。实际时间取决于火力、切块、锅具和操作速度。

- 「现在先做什么？」依据已完成与运行中的步骤回答。
- 「需要多少生姜？」按当前人数给出整餐合并量与各道菜的分量。
- 「肉还硬怎么办？」多道肉菜时先确认菜品，避免改错计时。
- 「红烧肉还硬怎么办？」查看是否已有运行中的慢炖计时，以及是否接近参考结束。
- 「那还要多久？」沿用刚才明确过的菜品，读取包含延长时间的倒计时。
- 「没有料酒怎么办？」按所选菜品给出内置处理建议，必要时可列入待准备。
- 「只有一只锅」与「只有一口灶」区别处理；当前支持单灶调度，不承诺自动解决单锅盛出、清洗和保温。

## 来源与边界

31 道菜的技法参考 [HowToCook](https://github.com/Anduin2017/HowToCook)，家常豆腐为自编配方；西葫芦炒蛋与蒜苔炒肉参考下厨房公开页面，记录作者、原始标题和具体链接，未使用第三方图片或原文，油盐用量和计时由掌勺独立整理。用量、步骤拆分与时间采用本项目的整理版本，不标称为外部原文、营养方案或厨师实测配方。各条来源和改编差异记录在 `sources.ts` 并显示在页面；HowToCook 当前使用 [Unlicense](https://github.com/Anduin2017/HowToCook/blob/master/LICENSE)。本项目未复制其图片或营养功效表述。

鸡肉熟度相关答疑参考 [FoodSafety.gov 安全最低内部温度表](https://www.foodsafety.gov/food-safety-charts/safe-minimum-internal-temperatures)。油锅起火的应急提示参考[国家消防救援局](https://www.119.gov.cn/kp/hzyf/jt/2025/52074.shtml)。这些答疑不能替代现场判断。

预算参考表是内部演示假设，不是市场价格采集；按每种食材的包装组合生成建议，不优化优惠券或配送费用。已有食材意味着用户确认足量，不是称重库存。

当前未接入自由生成的大模型、视觉识别或语音。完整菜谱检索默认使用公开 HowToCook 来源，无需密钥。下厨房为可选搜索来源，经服务端 Tavily 密钥调用；原页无法读取时明确显示仅链接或部分内容。它只能回答列明范围内的问题；之后接入模型时应继续保留确定的食材计算、结构化动作与当前状态校验。

## 手机使用与到点提醒

网站可以“添加到主屏幕”，以独立应用的方式打开（`public/manifest.webmanifest`，图标由 `scripts/generate-app-icons.mjs` 生成）。`public/sw.js` 只负责可安装和点击通知回到页面，不缓存任何内容，部署后不会出现旧版本。

开始做饭时（或点做饭页工具栏的“开启到点提醒”）会开启提醒，逻辑在 `hooks/use-cooking-alerts.ts`：
- 做饭期间请求屏幕常亮，切回页面后自动重新获取。
- 炖煮、蒸制、泡发、腌制等等待步骤到参考时间时，响铃、振动并在页面显示提示；页面在后台时另发系统通知。延长计时后会重新提醒，打开页面时已经过时的计时只显示、不补响。

限制：提醒依赖页面仍在运行。关掉页面、锁屏或被系统挂起后，浏览器不会再执行计时，因此可能收不到提醒，实际做饭仍建议另设闹钟。iPhone 需要先“添加到主屏幕”并从图标打开才能收系统通知（iOS 16.4+）；静音开关打开时没有铃声。页面无法控制炉灶或验证实际熟度。

站点延续已有 Sites / Vinext 项目身份与访问范围。`.openai/hosting.json` 为部署配置，`dist/` 为构建输出。

木耳泡发步骤另参考[中山市市场监督管理局](https://www.zs.gov.cn/zszjj/gkmlpt/content/2/2538/post_2538512.html)，不沿用长时间常温泡发。蛋炒饭的熟饭准备与保存时间需由用户核对，计划不包含从生米煮饭；新增菜谱水量随人数缩放，火候和用时仍为参考，大份量可能需要分批。

## 菜谱版本维护

菜名 ID 与别名用于解析用户菜单；做法 ID 用于选择、计时和答疑。已有做法的用量、步骤、来源有实质变化时需增加 `revision`，不能只覆盖内容继续沿用修订号。计划保存 `dishIds`、所选 `recipeIds`、`recipeChoices` 与 `recipes` 快照；库里的新版本不会自动覆盖已有计划。换一份做法只替换目标菜谱，并给新计划新的身份以失效旧问答动作。

本轮额外做法：红烧肉酱香免炒糖色版、番茄炒蛋多番茄浓汁版、西兰花蚝油蒜汁版、土豆丝青椒酸辣版、手撕包菜五花肉版、西葫芦炒蛋番茄合炒版、香菇滑鸡鲜香菇清蒸版。

即时搜索结果先成为候选做法，经用量、步骤、来源和保存范围核对后，再进入同一选择与快照流程。


## 在线完整菜谱

菜单先匹配内置菜与本机导入库，只有未知菜名进入联网检索。默认读取 [HowToCook](https://github.com/Anduin2017/HowToCook) 固定 commit `308cc8b7dab1da84b20e7fafdf836a715437f582`：该版本公开索引含 374 个菜谱 Markdown 路径。运行时搜索索引并获取匹配全文，最多三份；索引缓存一小时，原文按不可变路径缓存，保留实际读取时间。GitHub API 限流或失败时回退读取该固定版本的公开 README 索引。网络不可用时返回错误，不用假数据替代。

搜索结果按实际索引显示数量，374 份文件包含饮品、酱料、半成品及 1 份模板，并不表示 374 道家常菜或全部可直接生成计划。菜名匹配优先采用原名、常用食材别名和关键词，再对可以完整识别的食材组合匹配相近技法；必须包含全部所搜食材，不替换肉类。比如“土豆烧牛肉”可找到“西红柿土豆炖牛肉”，但会明确标为相近做法、提示额外食材。明确选用后保留原谱真实标题与差异说明，再以用户所搜名称衔接本餐；不会静默改名。

HowToCook 使用 Unlicense，完整用料与原文步骤可合法保留。候选预览显示归属、固定原页、许可、读取时间、原谱人数、食材以及每步时间依据。明确的 g/ml/个等量自动解析，未知“适量/一勺”等不猜数；完全可计算的配方可点击“使用这份做法”，直接生成清单和单/双灶排程，仍允许编辑。可选配料仅放在说明，不混入必选定量清单。

原文明确时长标为 source；没有明确时长的步骤使用简单排程估计，明确标为 estimated，不当作原谱声明或熟度保证。锅具按操作推定；不支持的烤箱、压力锅等设备和超过支持时长的步骤会阻止直接应用。原谱人数缺失或存在范围时需要审核；用户改人数记录为 user，不再声称源作者给出该人数。

导入配方按 2 人基准保存、按本餐人数缩放食材清单。步骤保留原文中的数字，不做全局数值替换；预览、配方提示和正在操作卡均说明以本餐清单为准。没有价格参考的新食材保留数量并明确未估价，当前金额不被当成完整总价或预算充足。

本机保留最近 20 份导入配方，与当前选中版本分别保存；手机和电脑不同步。来源、食材定义、步骤和时间依据随冻结快照保存；烹饪中锁定，刷新/改灶台不重读上游覆盖本餐版本。

### 可选下厨房搜索

页面可切到下厨房，调用 [Tavily Search API](https://docs.tavily.com/documentation/api-reference/endpoint/search)，限定域名和最多三份候选。不把搜索摘要当成配方；正文缺失时标为 link-only，不能直接生成计划。遇到验证码、403、429 或重定向会停止，不绕过验证。可在原站查看后粘贴用料并手动整理，粘贴文本仅在本机解析。

Tavily 密钥仅通过 Sites 运行时 Secret `TAVILY_API_KEY` 设置，不能写源码、聊天、前端变量或 hosting.json。环境修订需部署已保存版本后应用。HowToCook 默认搜索不依赖这个密钥。联网搜索只发送菜名，输入原页链接只请求支持的公开来源。

API 仅接收同源 POST 和小体积 JSON，限制查询长度、抓取来源、超时及正文大小，结果最多缓存十分钟。匿名 API 有每实例每来源每分钟 8 次、总计每分钟 60 次的保护；该内存限制不能替代多实例的全局配额，使用付费服务还需在供应商设置额度。

### 真实流程验收

已通过真实网络检索“蚂蚁上树”（不在内置 34 菜中），读取 9 项定量食材、10 原文步骤，原谱明确 2 人份。将其与番茄炒蛋、拍黄瓜组合为 3 人份，粉丝按干重 120g、猪肉末 225g；单/双灶均可完成 14 任务并通过 JSON 快照恢复。页面实测也走完 14/14，刷新保留泡发计时、版本与来源，390px 视口没有横向溢出。这里验证软件流程，没有进行实体试烹。

可对运行中的本地或线上站点执行同一个验收：

```sh
node --experimental-strip-types scripts/verify-live-recipe.ts http://localhost:5173
```

脚本从真实 API 获取菜谱，使用与页面相同的转换器和规划器，检查清单、来源、单/双灶资源、全任务完成和保存恢复，输出 `outputs/complete-live-recipe-check.json`。此目录不提交。

新增文件：`open-recipes.ts` 为公开索引/正文 provider，`source-draft.ts` 为候选转换器，`source-schema.test.ts`/`open-recipes.test.ts`/`source-draft.test.ts` 验证双来源、许可、缺失字段与估计时间边界。
