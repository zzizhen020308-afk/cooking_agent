# 掌勺 · Kitchen companion

一个可运行的中文做饭助手原型：输入菜名、人数和预算，得到菜谱、采购清单和多菜协同烹饪引导。目标场景是上海、叮咚买菜与盒马鲜生。

## 当前实现

- 支持 8 道自编示例菜谱及常见别名，每餐 1–4 道，1–6 人。
- 保持用户点菜顺序，识别简单否定和「预算 80 元、2 人份」这样的限制。
- 缩放用量、合并共用食材、扣除已备足量食材，按整包装计算采购。
- 比较两家**合成商品目录**的整单总额，包含示例配送费与包装费。
- 超预算、未知菜、无效输入、过期报价阻止模拟下单；修改清单后取消旧的模拟订单。
- 模拟订单具有重复点击保护。页面多处说明不会付款或配送。
- 生成步骤依赖图和预计时间表，限制一个人、两口灶及同类锅具并发占用。
- 实际烹饪按步骤依赖推进；快手热菜等待长炖菜接近完成再推荐。
- 炖煮倒计时、延长 5 分钟、手动熟度确认、演示快进、刷新恢复进度。
- 浏览器本地保存当前计划、模拟订单和烹饪进度；采购清单可复制或下载。
- 响应式中文界面、原生对话框与键盘操作。食物插画为本项目 SVG 素材。

## 运行

需要 Node.js 22.13+（测试使用 Node.js 24 的原生 TypeScript 支持）。

```sh
npm run install:ci
npm run dev -- --host 127.0.0.1
```

开发地址由终端输出，默认 `http://127.0.0.1:5173/`。

```sh
npm run test
npm run typecheck
npm run build
```

## 结构

- `app/page.tsx`：点菜、采购、烹饪三段用户流程，以及本地状态保存。
- `app/globals.css`：响应式视觉与交互样式。
- `lib/kitchen/catalog.ts`：自编菜谱、规范化食材、合成商品与平台费用规则。
- `lib/kitchen/engine.ts`：意图解析、用量合并、包装组合、报价、调度、订单校验。
- `lib/kitchen/providers.ts`：将来服务端平台适配器的接口合同与接入状态。
- `tests/kitchen.test.ts`：核心预算、覆盖率、订单、状态依赖和资源约束检查。

## 接入真实 Agent 的下一步

当前自然语言处理使用本地规则，**尚未接入大模型**。原型可作为确定性执行层，后续在服务端增加模型规划器：

1. `interpret_meal_intent` 将指令转换为菜名、人数、预算、忌口及已有食材的结构化输入。
2. `search_recipes` 检索有来源与使用许可的菜谱，返回可校验的食材、单位、锅具与步骤依赖；缺少关键信息时再澄清。
3. 本执行层验证菜谱与用户限制，计算食材需求；由授权平台适配器检索真实 SKU 与报价。
4. 服务端重新计算整单价格、库存、配送范围和时段，提供可核对的结算页。
5. 用户授权后提交订单，使用幂等键；超时先查单，避免重复购买。记录真实订单号并订阅状态。
6. 食材备齐后进入烹饪会话；手机 App 或小程序阶段补充可靠计时提醒与语音交互。

模型不直接决定支付金额，也不使用自造 SKU、库存或下单成功状态。真实购买前须用服务端报价与消费者授权校验，而不能信任浏览器状态。

## 真实买菜平台的核实情况（2026-11-09）

已找到 [盒马开放平台](https://openapi.hemaos.com/) 与 [叮咚三方合作平台](https://link.ddxq.mobi/)。这些入口的存在不足以确认第三方应用拥有消费者侧搜索、购物车、代下单或支付能力。盒马相关公开[商家授权说明](https://open.alitrip.com/docs/doc.htm?articleId=118185&docType=1&treeId=552)描述的是商家/ERP 场景，不能据此当作消费者购买授权。

本仓库未访问平台私有接口、未保存买菜账号或支付凭证。真实接入需要向两家平台确认业务合作范围与授权接口。若暂不能提供消费者代下单能力，可先交付「规范化采购清单 → 用户在买菜 App 核对并付款」的实用版本。

## 原型限制

- 所有价格、商品、库存、免配送门槛均为合成示例，不代表平台实时信息。默认三菜两人份的叮咚示例总额为 ¥86.80。
- 商品组合按每种食材最低成本挑选，再计算整单费用；尚未遍历凑单免运费、优惠券或跨店拆单的全局组合。
- 「已有」表示用户确认足量，尚无称重库存管理。烹饪用量按食材原始单位缩放，未实现可食率或家庭成员营养需求。
- 烹饪时间是参考；页面不检测食物熟度、不控制灶台。关页后不保证提醒，实际做饭应另设闹钟并查看火候。
- 数据仅在当前浏览器本地保存，未提供登录后的跨设备同步、多人厨房和真实订单服务。
- 不能将前端模拟订单、内存幂等或前端报价校验直接用于真实付款。

部署配置沿用 Sites Vinext / Cloudflare Worker 模板。`.openai/hosting.json` 保存本 Site 身份，`dist/` 为构建输出。
