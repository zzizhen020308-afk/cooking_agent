# 掌勺 · 烹饪陪伴助手

当前版本聚焦「选菜谱 → 备菜建议 → 结合实际步骤答疑并做完一餐」，支持 8 道内置菜谱。无需模型 API，问答在浏览器本机按明确的规则处理。

## 已实现

- 按菜名、人数、预算、一口或两口灶及可用时间建立整餐计划。
- 缩放食材用量、合并共用食材、扣除已备足量食材，提供参考包装与可复制、下载的备菜建议。
- 费用以区间展示，标明为内部参考值，未含配送、包装；没有商家商品、库存、订单或支付能力。
- 菜谱详情显示整理日期、原创或参考来源，以及与参考做法的差异；参考链接可直接打开。
- 烹饪按步骤依赖推进，一个人操作，遵守当前灶台数量及锅具占用；快手热菜接近长炖菜完成时再推荐。
- 内置答疑读取当前菜单、人数、步骤、计时、已有食材及选择的菜品范围。
- 支持份量、火候、加水、缺料、口味、步骤顺序、剩余时间及单灶重排等常见问题。
- 多道菜可能对应问题时先澄清；未收录的菜或问题明确告知范围；不判断食物实际熟度。
- 接近炖煮参考结束时，仍硬的红烧肉或排骨可由用户确认延长 10 分钟；尚早时先提示按原计时观察。已经逾时的提醒从确认时重新计足追加时长，保留实际开始时间。
- 单灶调整保留已完成步骤和计时；两锅已同时加热时，拒绝直接切换为单灶，提示先处理现场。
- 缺料建议可纠正「家里已备」假设；动作按钮过期后不能继续修改旧计划。
- 进度、单灶设置、延长时间与最近 20 条问答保存在本机，刷新后恢复。
- 旧版 v1 菜单、有效步骤进度迁移到 v2；旧模拟订单不进入当前流程。

## 运行与验证

需要 Node.js 22.13+。原生 TypeScript 测试使用 Node.js 24。

```sh
npm run install:ci
npm run dev -- --host 127.0.0.1
npm test
npm run typecheck
npm run build
```

开发地址默认 `http://127.0.0.1:5173/`，以启动输出为准。

## 主要结构

- `app/page.tsx`：选菜、备菜、烹饪三个界面与本机进度保存。
- `components/kitchen/cooking-help.tsx`：本餐问答、澄清选择、回答依据及确认操作。
- `lib/kitchen/catalog.ts`：2 人基准整理配方、规范食材与内部包装参考。
- `lib/kitchen/sources.ts`：每道菜的来源、参考链接、改编说明、版本和答疑依据。
- `lib/kitchen/engine.ts`：需求合并、购买建议、预算区间、灶台调度和计时更新。
- `lib/kitchen/advisor.ts`：有限规则答疑，输出正文、澄清选项、依据和可选的结构化动作。
- `tests/`：份量、计划资源、完整单/双灶流程、问答范围、计时与动作校验。

## 例子

「红烧肉、番茄炒蛋、山药排骨汤，2 人」默认双灶参考约 93 分钟，单灶参考约 146 分钟。实际时间取决于火力、切块、锅具和操作速度。

- 「现在先做什么？」依据已完成与运行中的步骤回答。
- 「需要多少生姜？」按当前人数给出整餐合并量与各道菜的分量。
- 「肉还硬怎么办？」多道肉菜时先确认菜品，避免改错计时。
- 「红烧肉还硬怎么办？」查看是否已有运行中的慢炖计时，以及是否接近参考结束。
- 「那还要多久？」沿用刚才明确过的菜品，读取包含延长时间的倒计时。
- 「没有料酒怎么办？」按所选菜品给出内置处理建议，必要时可列入待准备。
- 「只有一只锅」与「只有一口灶」区别处理；当前支持单灶调度，不承诺自动解决单锅盛出、清洗和保温。

## 来源与边界

7 道菜的技法参考 [HowToCook](https://github.com/Anduin2017/HowToCook)，家常豆腐为自编配方。用量、步骤拆分与时间采用本项目的整理版本，不标称为外部原文、营养方案或厨师实测配方。各条来源和改编差异记录在 `sources.ts` 并显示在页面；HowToCook 当前使用 [Unlicense](https://github.com/Anduin2017/HowToCook/blob/master/LICENSE)。本项目未复制其图片或营养功效表述。

鸡肉熟度相关答疑参考 [FoodSafety.gov 安全最低内部温度表](https://www.foodsafety.gov/food-safety-charts/safe-minimum-internal-temperatures)。油锅起火的应急提示参考[国家消防救援局](https://www.119.gov.cn/kp/hzyf/jt/2025/52074.shtml)。这些答疑不能替代现场判断。

预算参考表是内部演示假设，不是市场价格采集；按每种食材的包装组合生成建议，不优化优惠券或配送费用。已有食材意味着用户确认足量，不是称重库存。

当前未接入自由生成的大模型、联网搜索、视觉识别或语音。它只能回答列明范围内的问题；之后接入模型时应继续保留确定的食材计算、结构化动作与当前状态校验。

计时依赖当前页面，关页后不保证提醒；实际做饭应另设闹钟并留意火候。页面无法控制炉灶或验证实际熟度。

站点延续已有 Sites / Vinext 项目身份与访问范围。`.openai/hosting.json` 为部署配置，`dist/` 为构建输出。
